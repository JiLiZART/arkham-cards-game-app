## Context

The engine's scenario structure is Night of the Zealot's: `GameState.act` and `GameState.agenda` are one `InstId | null` each (`src/engine/world/types.ts:453`), `PILE.ActDeck` and `PILE.AgendaDeck` are two fixed piles (`world/constants.ts`), `createGame` (`index.ts:255`) builds them from `ScenarioDef.acts`/`agendas: string[]` and moves the first card of each into `ZONE.Act`/`ZONE.Agenda`; `checkDoomHandler` (`rules/scenario.ts:141`) compares `doomInPlay` with the one agenda. A card's other side is reached only by `setCode` (`context.ts:271`), which swaps the definition and nothing else; `backSide()` (`rules/scenario.ts:148`) runs an act's or agenda's revelation abilities as the "back". `flags.beneath` (`world/flags.ts:89`) maps a location to one card and `flags.underAct` (`flags.ts:134`) holds a list; `tokenX` (`rules/tokens.ts`) reads `underAct`. `ZONE.Removed` is the only out-of-play zone and `moveCard` (`movement.ts:81`) discards attachments on the way. Locations from an encounter set always go to `ZONE.SetAside` (`index.ts:242`). `revealLocation` is a typed step (`STEP.RevealLocation`) with no window after it. `checkDefeatHandler` and `defeatedHandler` (`rules/investigators.ts:341-350`) and `defeatEnemyHandler` (`rules/enemies.ts:352`) are unconditional. `spawnHandler` (`rules/enemies.ts:92`) understands a location name, `emptyLocation`, `farthestEmptyLocation` and `Engaged with Prey`; `preyCandidates` (`enemies.ts:56`) knows `bearer`, `only`, `highest`, `lowest`. `TokenEffect` has one `modifier`. `ScenarioFacts` (`campaign/types.ts:40`) has `notResigned` but no resigned or defeated list. Scripts queue steps only through the verbs in `api.ts` (ADR-0034), hooks are typed in `ScriptHooks` (`world/types.ts:576`, ADR-0028), deferred rules are typed step kinds (ADR-0033), tests drive games through `kits/driver.ts` (ADR-0029). `scenario-import-fixes` already drops a `Xb` code from a scenario's pools when `X` is there (its design, decision 4) and leaves the flip to this change.

What the campaign changes ask of this change, by name: `campaign-the-dunwich-legacy` (location removal, the void, locations in the encounter deck, cards beneath locations and the agenda, several act versions, flipping a location back, random setup ops, story cards, "would be defeated", a `locationLeavesPlay` hook, the `instead` token form, a `defeated` list in `ScenarioFacts`), `campaign-the-path-to-carcosa` and its Return (Hidden aside, two agenda decks, `flip` and swap, the beneath-act Monster pile, story backs, random act versions, the horror-defeat replacement, `modifierIf`), `campaign-the-forgotten-age` (three act decks trimmed by `when`, act backs that flip into locations, assets and enemies, story cards, location stacking, locations in the encounter deck, random setup ops, the `instead` form), `campaign-return-to-the-night-of-the-zealot` (the reveal trigger; "one of [a, b] set aside at random with the rest removed", "agenda 1 at random with the chosen card's back set aside", "3 removed at random" from a side deck), `player-cards-ptc` (Sophie's `flip`, Sefina's `beneath` pile with `drawFromBeneath`), `campaign-flow-compiler-fixes` (the engine's "resigned or defeated" answer).

## Goals / Non-Goals

**Goals:** every mechanic in the proposal as engine state, steps, verbs, hooks and schema, each with a driver test; `ENGINE_VERSION` 8; the UI able to draw several act and agenda stacks, a void, a pile beneath a card and a story page; nothing in `content/` beyond the schema and `implemented.ts`.

**Non-Goals:** per-instance connections and grids (`engine-location-instances-grid`); Patrol, Swarming, Veiled, Hidden and the rest (`engine-generic-keywords`); seal, release, bless and curse (`engine-bless-curse`); the import of any scenario file (`scenario-import-fixes`, the campaign changes); the enemy-vs-enemy attack (Predator, Warring: `engine-generic-keywords` and `campaign-side-war-of-the-outer-gods`); the keys, floods, supplies, days and partners of the cycle changes; Time Warp; the `enemyEntersPlay` and end-of-enemy-phase windows (`campaign-the-dunwich-legacy` adds them as windows where it needs them).

## Decisions

1. **Act and agenda decks are named piles; the one-deck scenario is deck `a`.** `ScenarioDef.acts` and `agendas` accept `Entry[]` (one deck, named `a`) or `Record<string, Entry[]>`. `PILE` gains `act:<deck>` and `agenda:<deck>`; `GameState.acts`/`agendas: Record<string, InstId | null>` replace `act`/`agenda`; `currentAct(game, deck = "a")` and `currentAgenda` keep every caller working; `AdvanceAct`/`AdvanceAgenda` steps gain `deck`; `checkDoomHandler` walks every agenda deck and advances each whose threshold is met in deck order; `placeDoomHandler` with `card: "agenda"` and several decks asks the lead (`CHOICE.Target`, key `doomOnWhichAgenda`, `auto: true` so one deck never asks). `tokenX("actStage")` reads deck `a` unless the token line names a deck. The scenario reference card becomes an instance in `ZONE.Scenario` at setup so `beneath:<scenarioCard>` exists. _Alternative:_ a script-held second deck (ptc.md §2 "scenario script plus an engine hook") — rejected: doom placement, advancement and the UI stacks are engine rules; three campaigns need it.

2. **An entry with versions is `{ oneOf: string[]; when?: LogCondition }`.** At `createGame`, the first version whose `when` holds is created; with no `when`, one at random from the seeded RNG; the others are not created (a scenario that needs the other's back, as Return to The Midnight Masks does, lists it under `setAside`). `resetDeck { deck }` is an effect op that moves the current card and the advanced cards back into the pile in order (Children of Blood's act 13007). _Alternative:_ a `setup` hook per scenario — rejected: four campaigns say it in data and `scenario-import-fixes` compiles `when` already.

3. **A face is a field, and `flip` is one op over `setCode`.** `CardInst.face: "a" | "b"` and `defOf` resolves the shown code. `flip(game, id)` in `context.ts`: compute the other code (`code + "b"` or `code.slice(0, -1)`), `setCode`, then `moveCard` to the zone of the new type when it differs (`story` → out of the play area at the same location, `enemy` → `ZONE.Enemy` at the location the card names or stays, `location` → `ZONE.Location`, `asset` → `ZONE.Play`), keeping counters, attachments, `location` and `controller`. `swap { with: code }` is `flip` followed by replacing the instance's code with a set-aside copy's and moving the copy out (the Bystander swap). `STEP.ResolveStory { card, you }` shows the story (an event `StoryShown` the UI stops on), runs the face's revelation abilities, then applies `story.after` (`flipBack` | `remove` | `stay`). Veiled (`engine-generic-keywords`) and Mirage (`engine-eoe-partners-frost`) call `flip` + `resolveStory`. The loader marks `Xb` as a face of `X` (`db.cards[X].back = Xb`), and `createGame` and the setup ops never create a `b` code. _Alternative:_ `setCode` alone, as today — rejected: zone and type change with the face, and the loader puts `b` sides into decks (ptc-part3.md:31).

4. **`beneath:<InstId>` is a pile; `underAct` and `flags.beneath` go.** `PILE` names it; `moveCard(game, id, ZONE.Beneath, under)` pushes; `drawBeneath { from, who }`, `revealBeneath { from }`, `shuffleBeneath`, `moveBeneath { from, to: zone }`; when the holder leaves play, its pile goes where its card data says (`beneathOnLeave: "discard" | "stay"`; default discard). A beneath card is `zone: "beneath"` with `holder` as its `location` field, so the store's "follow the holder" is the location rule already used by attachments. Swarm cards (`engine-generic-keywords`) and Sefina's events are the same pile with a flag. _Alternative:_ `flags.beneath` as an array — rejected: a flag isn't a pile; the snapshot, undo and the UI count piles.

5. **Removal is one step; the void is one zone.** `STEP.RemoveLocation { location, investigators: "defeat" | "move" , to?: InstId }` in `rules/scenario.ts`: for each investigator there, `Defeated` or `Move`; enemies and attachments there discarded (enemies with Victory to the display, as `defeatEnemy` does not: they are discarded, per the rules "enemies at that location are discarded"); the location to the victory display when `victory` and no clues, else the encounter discard; `fireScenarioHook("locationLeavesPlay", id)` before the pile move; `connections()` already filters to `ZONE.Location`, and `engine-location-instances-grid` prunes its instance links in the same step. `ZONE.Void` is a zone `moveCard` treats like `SetAside` but keeps attachments, counters and `engagedWith` cleared; `searchEncounterDraw` and `searchEncounter` gain `zones?: ("deck" | "discard" | "void")[]`. _Alternative:_ `ZONE.Removed` for the Hunting Horror — rejected: removed is "no further interaction" (Grimoire, Removed from Game) and loses attachments.

6. **A location is an encounter card when its set says so.** `ScenarioDef.encounterLocations: string[]` (sets) and `sideDecks` entries may name location sets; `createGame` routes those locations to the deck instead of `SetAside`. `drawEncounterHandler` on a location runs `Revelation`, whose default for a location is `putIntoPlay { connectedTo: "you" }` (its text may say otherwise through abilities); `discardEncounterUntil` gains `type: "location"` and hands the location to the same path. _Alternative:_ a per-scenario `setup` hook moving them — rejected: Lost in Time and Space, its Return and The Drowned City (tdc.md:221) say it in data.

7. **Random setup ops are four steps.** `chooseRandom { from: string[]; n?: 1; then: "putIntoPlay" | "setAside" | "act" | "agenda"; deck?: string; rest: "remove" | "setAside" | "keep" }`, `removeRandom { from: "setAside" | "encounterDeck" | `sideDeck:${name}`; n; filter?: CardFilter }`, `shuffleSetAside { filter? }`, `putRandomIntoPlay` (exists) gains `filter`. Each draws from `randInt(game.s, …)`. `putBeneath { cards: string[] | { filter, n }; under: code | "scenario" | "act" | "agenda"; facedown: true }` is the fifth. _Alternative:_ one `random` step with a mode — rejected: the Return-to and PtC changes already name these four.

8. **"After you reveal this location" is a window.** `revealLocationHandler` emits `EVENT.LocationRevealed` and pushes `Window { trigger: "afterReveal", data: { location, inv } }` after the clues; `Ability.trigger: "revealed"` on a location is a reaction in that window with `you` the revealer, forced when `forced: true`. Return to NotZ (50020, 50021, 50034) and PtC (03050, 03052, 03058, 03128–03138) read as data.

9. **"Would be defeated" is a window before `Defeated` and `DefeatEnemy`.** `checkDefeatHandler` pushes `Window { trigger: "wouldBeDefeated", data: { inv, by: "damage" | "horror" | "both" | "effect" } }` then `Defeated`; a `wouldBeDefeated` ability (kind `replacement`) or `fireScenarioHook("wouldBeDefeated", inv, by)` returning `true` cancels the `Defeated` step through the existing cancel keys (`cancelEvent`). `defeatEnemyHandler` does the same with `{ enemy, by }`. Dim Carcosa's sanity rule is a scenario hook; 03042, 03269 and the Children of Blood predator replacement are card abilities. _Alternative:_ a flag `cannotBeDefeated` — rejected: the replacements do things (shuffle, heal, discard), not just prevent.

10. **Interludes are a step; checkpoints are a resolution flag.** `STEP.ReadInterlude { id, choices }` sets `pending` to a `CHOICE.Generic` with the interlude's options (key `interlude:<id>`), the UI shows the story text from the scenario's `interludes[id]` (schema: `{ text: i18n key; choices: { id; record?: notes }[] }`); the answer writes `campaignNotes`. A resolution with `checkpoint: true` runs `Resolution` as today but `campaign.ts` writes `count:` and `cards:` notes for every location in play, its clues and named tokens, each story asset's controller, each investigator's named counters and the scenario card's beneath pile, and the flow's `applyScenarioEnd` skips experience and upgrades; the next part's setup reads the entries through `when` conditions and a `fromCheckpoint` setup step (locations, clues, tokens, assets by log). _Alternative:_ carrying the `GameState` into the next scenario (boxes.md #15, eoe.md #7 both prefer the log path) — rejected: a second part always has a from-scratch setup in the guide, so the log path is the one that covers both choices.

11. **Vehicles are a keyword and a field.** `keywords` gains `vehicle`; `InvRecord.vehicle: InstId | null`; `EnterVehicle`/`LeaveVehicle` are fast actions in `legalTurnActions` gated by `limitUses` per round; `Move` of a vehicle (an asset with a location, moved by its own ability through `moveCard`/`setCardLocation`) pushes `Arrive` for each occupant; `invsAt` is unchanged because an occupant's `location` is the vehicle's. `flags.noVehicles` (scope location or global) blocks entering. Two TIC scenarios, Film Fatale's Rocket Ship and the later boxes read it as data.

12. **Named tokens are a counter table.** `CardInst.tokens` and `InvRecord.tokens: Record<string, number>`; `placeTokens { name, amount, target }`, `removeTokens`, `moveTokens`; `Amount.tokensOn { name, target }`; `Condition.tokens { name, min, max, target }`; `tokenX` gains `tokensOn`. The UI shows the name and count on the card frame. _Alternative:_ widening `Counter` (`context.ts:208`) — rejected: `Counter` is a closed set the holder check guards; names are open.

13. **Spawn is an expression, shared with Patrol.** `Spawn = string | { at: "named" | "trait" | "empty" | "nearest" | "farthest" | "connected"; name?; trait?; empty?; to?: "you" | { code } | { trait }; unrevealed?: "ifAble"; or?: Spawn[] }`; `spawnTargets(game, expr, from)` in `queries.ts` returns the candidate locations; `spawnHandler` asks the drawer among several (`auto: true`); `spawnResolves` in `implemented.ts` accepts an expression. `prey` gains `{ nearestTo: CardFilter }` in `preyCandidates`. `engine-generic-keywords` parses "Patrol (…)" into the same expression.

14. **`instead` on a token line.** `TokenEffect.instead?: { when: Condition; modifier: number | { x } }`, read in `rules/skillTest.ts` where the symbol's modifier is computed, with the test's investigator as `you`. The PtC design calls this `modifierIf`; the field is `instead`, as `campaign-the-dunwich-legacy` and `campaign-the-forgotten-age` write it. `autoFail` as a result stays with `engine-tfa-supplies-vengeance-exploration`.

15. **Hooks added to `ScriptHooks`:** `locationLeavesPlay(game, location)`, `wouldBeDefeated(game, who: InvId | InstId, by): boolean`, `storyResolved(game, run, card)`. Verbs added to `api.ts`: `flip`, `resolveStory`, `removeLocation`, `readInterlude`, `putBeneath`, `drawBeneath`, `revealBeneath`, `toVoid`, `placeTokens`, `enterVehicle`, `leaveVehicle`; reads: `currentActs`, `currentAgendas`, `cardsBeneath`, `tokensOn`, `spawnTargets`, `inVehicle`.

## Risks / Trade-offs

- [Every caller of `game.s.act`/`agenda` changes] → `currentAct(game)` keeps the one-deck meaning; the boundary test's `game.s` list is unchanged; the corpus replays unchanged (no recorded game has two decks).
- [A `b` face already in a generated pool] → `scenario-import-fixes` drops it; the loader also refuses to create a `b` code and `check:content` reports any scenario file that lists one in `setAside` or `putIntoPlay`.
- [The checkpoint log cannot hold everything a table has (facedown order, attachments)] → the entries are what the guide's "take a break" list names; what it does not name is not carried, and the proposal says so under the FoF change.
- [`wouldBeDefeated` windows on every defeat slow the fuzz test] → the window is pushed only when a replacement ability or hook exists (`hasScenarioHook`, abilities index).
- [Spawn expressions that no card uses] → the enum is the union of the inspection reports' spawn lines (dwl, ptc, tcu, tde, boxes, sides); `implemented.ts` fails coverage for an expression the handler does not resolve.

## Migration Plan

Lands as one change behind `ENGINE_VERSION` 8; saves from 7 are refused (as the `nat-pack-cards` bump was). The corpus is re-recorded only if a snapshot differs because of the state shape (`acts`/`agendas` records), by the explicit script. No content file changes besides the schema; the campaign changes write the data.

## Open Questions

- The Grimoire has no entry for the rule that a location removed from play defeats the investigators there; the Essex County Express and Lost in Time and Space state it on the card. The default is "defeated"; a scenario names a move instead (decision 5).
- ADR-0021 and ADR-0023 (proposed) describe the store's piles and tables; this design adds piles (`beneath:<id>`, named act and agenda decks) and tables (`face`, `tokens`, `vehicle`) within them, so no supersession.
