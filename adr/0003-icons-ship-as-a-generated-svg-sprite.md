# ADR-0003: Icons ship as one generated SVG sprite with a provenance manifest

- Status: accepted
- Date: 2026-10-17

## Context and Problem Statement

The game's icons came from five IcoMoon fonts and fifteen PNGs copied from `inspired/`. Fonts flash blank until loaded, allow one colour per glyph, and only hold what was packed into them; PNGs are raster and fixed in size. The vector sources of the same icons, plus every encounter-set and scenario icon, are available in `inspired/svg-icons`, which never ships. A single rule is needed for how icons reach the page from now on, including for future campaign packs.

## Considered Options

- One SVG sprite generated by a script from the sources (the fonts' glyph sets plus what code and content reference), injected into the document once, drawn with `<use>` layers; a manifest records each symbol's source; `check:content` ties content's sets and scenarios to the sprite.
- Generated React components per icon, inlined in the bundle.
- Keep the icon fonts and add SVG only for new icons.

## Decision Outcome

Chosen option: "one generated sprite with a manifest", because it keeps one drawing path for every icon, recolours per layer, renders sharp at any size without a loading flash, and makes a new campaign's icons a rebuild of the sprite rather than code. Components were rejected for bundle weight and React re-rendering of static paths; keeping the fonts was rejected because two paths for one icon set drift.

### Consequences

- Good, because `IconName` and markup keys stay stable while the renderer changes underneath.
- Good, because provenance and completeness are checked by `check:content`, like the sounds.
- Bad, because the sprite (~150 KB over the wire) is one more file the table waits for on first load.
- Bad, because the five cardboard-token PNGs remain a second asset type until someone draws them as vectors.
