# Arkham Table

A browser version of *Arkham Horror: The Card Game* on a 3D table (React + react-three-fiber), with a rules engine in plain TypeScript. 1–4 investigators play hot-seat on one device. It ships the **Night of the Zealot** campaign and starter decks for the five core investigators.

Fan project for personal use. Card text comes from ArkhamDB and card images from arkham.build. The game is © Fantasy Flight Games.

## Run

```bash
npm install
npm run dev            # http://localhost:5173
npm test               # engine, content and UI-logic tests
npm run check:content  # validate every file under content/
npm run build
```

Card images are loaded from `https://cdn.arkham.build/optimized/<code>.webp`. That CDN sends no CORS headers, so the dev and preview servers proxy `/cards/*` to it (see `vite.config.ts`). The GitHub Pages build downloads the scans into the site instead (see Deploying). On another host, set up the same rewrite, or set `VITE_CARD_IMAGE_BASE` to a CORS-enabled mirror. When an image cannot load, the card is drawn from its data instead.

Icons are one SVG sprite, `public/icons/sprite.svg`, injected into the page before the first screen draws, so no icon ever flashes blank. `npm run import:icons` (`scripts/import-icons.ts`) builds it from the vector sources in `inspired/svg-icons`. The sprite holds every glyph of ArkhamCards' five IcoMoon icon fonts, which includes every encounter set and scenario they know, so a later campaign's icons need no new code. It also holds every name the code draws and every encounter set and scenario in `content/`. Codes the icon set spells differently (the core set's `torch`, `cultists` and others) are aliased under `extra` in the provenance manifest `content/icons/icons.json`, which lists each symbol with its source file and icon set. `check:content` fails when a set or scenario has no icon, or when the manifest and the sprite disagree. Only the cardboard tokens the icon set doesn't draw are PNGs: damage, horror, doom, the lead token and the connector plaques (from `inspired/icons`, cut out along the hand-made transparent copies in `inspired/icons/transparent`). The card backs come from ArkhamCards too, and the framed table background from `inspired/icons`; the card fonts are Teutonic, Teutonic RU and Alegreya. `scripts/extract-assets.sh` copies these into `public/icons`, `public/table` and `public/fonts`; it needs ImageMagick. All outputs are committed, so builds never read `inspired/`. Like the card scans, the art, icons, fonts and imported text are for personal use.

## Deploying

Every push to `main` deploys the game to GitHub Pages at **https://arkham.artkost.dev** (`.github/workflows/deploy.yml`). The workflow runs the tests, lint and content check, builds, and then publishes. A failing check publishes nothing and the site keeps the previous version. To deploy without a push, use Actions → "Deploy to GitHub Pages" → Run workflow.

- **One-time setup:**
  - Settings → Pages: Source "GitHub Actions", custom domain `arkham.artkost.dev`, Enforce HTTPS.
  - In Cloudflare DNS for `artkost.dev`: a `CNAME` record `arkham` → `jilizart.github.io`, proxy off (DNS only), so GitHub can issue the certificate.
- **Why a subdomain:** the account's user site has the custom domain `artkost.dev`, so `jilizart.github.io/<repo>/` redirects to `artkost.dev/<repo>/`, which Cloudflare serves as the portfolio. Without a custom domain, the game would live at `/<repo>/`: build with `PAGES_BASE=/arkham-cards-game-app/`, and every asset path follows (see below).
- **Card scans:** `npm run fetch:cards -- dist` downloads every scan the game uses (about 230 files, 46 MB) into `dist/cards`, so the map's WebGL cards load them from the same origin. They are cached in `.cache/cards` and never committed. A scan that can't be downloaded is listed in the log and that card shows its drawn face. The scans are publicly hosted on the Pages site.
- **Trying a deploy build locally:** `npm run build && npm run fetch:cards -- dist && npx vite preview`, then open http://localhost:4173/. Add `PAGES_BASE=/some-path/` to both commands to check a sub-path build.
- In code, files under `public/` are referenced with `asset("…")` from `src/ui/images.ts`, never with a leading `/`; a test enforces this.

## Layout

```
content/                         game data — no engine changes needed to add more
  packs/core/cards.generated.json  imported from ArkhamDB (never edit by hand)
  packs/core/cards.json            hand-written behavior & fixes, merged over the generated data by card code
  packs/core/scripts/<code>.ts     TS for cards the data format can't express
  investigators/<code>.json        hand-written deckbuilding rules, signature cards (replaces a generated one)
  investigators-generated/<code>.json  every regular investigator of the snapshot (npm run import:investigators)
  decks/<id>.json                  deck lists
  decks-generated/<code>-starter.json  the official starter decks from ArkhamCards
  pack-index.json                  which pack a card code comes from, so a deck's packs load before the cards are known
  campaigns/<id>/campaign.json     scenario order, chaos bags, campaign-log labels
  campaigns/<id>/scenarios/*.json  setup, connections, map layout, chaos token effects, resolutions
  campaigns/<id>/scripts/<scenario>.ts  objectives and scenario-specific hooks
  i18n/<locale>/{ui,cards,campaigns}.json            hand-written translations (English is the fallback)
  i18n/<locale>/*.generated.json   imported translations; the hand-written files win field by field
scripts/import-cards.ts          ArkhamDB → cards.generated.json
src/engine/                      rules engine (no React/three imports — enforced by ESLint)
src/content/                     zod schemas, loader, i18n
src/ui/                          React HUD + R3F table
```

## Adding cards

1. Import the card data. Every cycle comes from the local ArkhamDB snapshot in `inspired/arkhamdb-json-data` (commit `bd8d30e6de8236ad6f6973850a62875245abcd45`), one pack per snapshot folder:

   ```bash
   npm run import:cards -- --source arkhamdb-json-data --all          # every folder of the snapshot
   npm run import:cards -- --source arkhamdb-json-data --cycle dwl    # one folder; --root <dir> for another snapshot
   ```

   `--all` lists the snapshot's folders, not `cycles.json`, so the core folder's 2026 reprints are a pack of their own (`core_2026`) and the Return-to boxes share one (`return`). Bare duplicate stubs and the `01000` placeholder are left out. A record that fails the schema is reported with its code. The older `--pack <pack_code>` form still reads the ArkhamDB API. Either form only rewrites `cards.generated.json`.

   Only the core pack is in the first download. The other packs are separate chunks that `loadPack(pack)` fetches when a game needs them, together with that pack's translated text. Measured on 2026-10-18, the main JS chunk is 1,736 KB with the core pack alone, 5,469 KB with every pack eager, and 1,742 KB with lazy packs. Gzipped, those are 462 KB, 1,151 KB and 464 KB.
2. Describe behavior in `content/packs/<pack>/cards.json`:

   ```json
   "01088": { "abilities": [{ "kind": "onPlay", "effects": [{ "op": "gainResources", "amount": 3 }] }] }
   ```

   Ability kinds are `action`, `fast`, `reaction`, `forced`, `constant`, `revelation` (also an act's or agenda's back side), `onPlay` (also a skill card's effect when committed), and `elderSign`. Effects, conditions, triggers and modifiers form a closed vocabulary defined in `src/content/schema.ts`. Unknown names fail validation.
3. If something can't be expressed this way, set `"script": true` and add `scripts/<code>.ts` exporting a `CardScript`. Copy any existing script as a starting point.
4. Run `npm run check:content`.

## Russian card images

With the Russian interface, cards show Russian card images from `public/cards-ru` (WebP at half the scan size). The import takes them from three sources, best first:

1. **The per-card folders** in `inspired/Arkham_Horror_LCG/покарточная сборка`. Each file is named by the card's number in its cycle (`06_1.png` is card 6 with one copy, `104a`/`104b` the two sides of card 104), so the match is exact and needs no OCR. `scripts/ruFolders.ts` holds the naming rules and the folder-to-code table: `02_…` is cycle 02, `0xR_…` a Return-to box (codes 50 on), `SD_0k_…` a starter deck (60k), `SA_…` a standalone. Names outside the rules, such as minis and act sides, fall through to the next sources.
2. **Community cards** in `inspired/CARDS_ru`, matched by OCR.
3. **The print sheets**, the PDFs in `inspired/Arkham_Horror_LCG`, matched by OCR against their own cycle's cards only. Tokens, the playmat and the superseded starter-deck sheet are skipped. The Russian card names and texts follow what is printed on those images (`content/i18n/ru/cards.print.json`, layered between the imported translation and hand-written `cards.json`). Like the English scans, these images are publicly hosted on the Pages site.

To rebuild them, run `npm run import:ru-cards`. It needs `tesseract`, `pdfimages` (poppler), ImageMagick and `cwebp`, and downloads Tesseract's Russian data once into `.cache/tessdata`. The import:

1. extracts the card images embedded in the PDFs;
2. reads every candidate image with OCR (about 25 minutes the first time for some 10,900 images, cached in `.cache/ru-import`);
3. maps the folder files by number, and matches the other images to a card code by name, text, orientation and level;
4. writes the manifest `content/i18n/ru/images.json`, the WebP files and `src/ui/ruImages.generated.json`.

Uncertain matches are left out and listed on one contact sheet per code range, `.cache/ru-import/review-<range>.html` (`01` core, `02` Dunwich, `52` Return to Carcosa…), next to the English scans. Pin or reject a match in `content/i18n/ru/images.overrides.json` (`{"01111:back": "inspired/…/Кабинет.jpg"}`, or `null`) and rerun; the same inputs and overrides always give the same output. For new cards, add their printed text to `cards.print.json`; `npm run check:content` rejects unknown codes and icon tokens there.

The run of 2026-10-18 gave 3,833 of 7,812 card sides a Russian image: 3,382 from the folders, 374 from the community cards and 77 from the print sheets. Of the OCR matches, every one scoring under 0.65 was checked by eye and 7 were rejected. About 7,500 candidate images match no card side; most are copies, encounter backs or sides the folders already cover.

## Translations

Translations are imported, not typed in:

```bash
npm run import:i18n -- --locale ru               # card names, traits and text for every pack from the snapshot's
                                                 # translations; campaign/scenario names, intros, resolutions, log
                                                 # labels, encounter sets and matching UI labels from inspired/ArkhamCards
npm run import:cards -- --pack core --locale ru  # card names, traits and text from ru.arkhamdb.com (older path)
```

Both write only generated files: `content/i18n/<locale>/*.generated.json`, plus `content/i18n/<locale>/packs/<pack>.generated.json` for every pack but core, loaded with its pack. `check:content` prints, per pack, how many cards have text in each locale; for Russian it is 5,544 of 5,859, and flavour text is not imported. Fix a string by putting it in the hand-written `ui.json`, `cards.json` or `campaigns.json` next to them; re-running an import never touches those. Campaigns and scenarios name their ArkhamCards counterpart with `i18nId`. If ArkhamDB is unreachable, the card import exits with an error and keeps the old file.

## Menu art

`npm run import:art` extracts the menu backgrounds from the core rulebook (`inspired/ahc100_rulebook-web.pdf`, needs `pdfimages` and ImageMagick) into `public/art/` (760 KB) and lists their source pages in `content/art/art.json`: the cover painting for the title (the rulebook's cut-out of it, with its soft mask, fading into the dark), a portrait and a landscape parchment page with the vine border, and five pages with the class emblems (kept for the investigator and catalog screens). A tile's description comes from the campaign guides (`prologue` and `scenarioNames` in each `campaign.json` and in each locale's campaign text); the Russian campaign guide PDFs in `документы` open the same way, with the epigraph and a list of scenarios. The text adds about 105 KB to the main JS chunk (1,979 KB, 531 KB gzipped).

## Investigators

The five core investigators are written by hand. The rest are **generated** from the snapshot (`npm run import:investigators`, run after `import:cards` and `import:i18n`): an `InvestigatorDef` for every regular investigator (73 besides the core five; parallel fronts and story investigators are left out) with the name and class, the pack, signatures, fixed weaknesses, deck size and the deckbuilding options in ArkhamDB's full grammar (faction, level, trait, tag, type, name, text, uses, limit, at least, not; a key the importer doesn't know is kept under `raw`). Names in other languages come from the imported pack text, so the picker can show them before a pack loads. The official starter decks come from ArkhamCards' `starterDecks.ts` (a list naming a card the snapshot lacks is left out, the 2026 core's reprint stubs are mapped to the original card). A file in `content/investigators` or `content/decks` with the same code wins. The deck validator checks the options it understands (faction, level) and passes what it can't judge until the deck builder (change `deck-builder`) knows more. ArkhamCards' starter lists for Tommy Muldoon (29 cards) and Dexter Drake (32) don't add up to 30 and are kept as published; the deck step says so. The new-game wizard lists every investigator with class and cycle filters and a search by name (in the game's language, and English); an investigator whose card has no written abilities carries a "partly implemented" note, and one with no deck is greyed as needing one. Starting a campaign loads the packs of the investigators and of every card in their decks (found by `pack-index.json`) before it begins; a saved game asks for them again when it is restored.

## Campaigns

Night of the Zealot is written by hand: every card it uses has its behaviour in data or a script, so it plays by the rules. Every other official campaign is **generated** from ArkhamCards' campaign guides (ADR-0007):

```bash
npm run import:campaigns              # content/campaigns-generated/<id>/, from inspired/ArkhamCards/assets/generated/all_campaigns.txt
npm run import:i18n -- --locale ru    # then their Russian names, intros, resolutions and log labels
npm run import:icons                  # then the icons of their encounter sets (a second sprite)
```

The import writes 36 campaigns with 149 scenarios: The Dunwich Legacy, The Path to Carcosa, The Forgotten Age, The Circle Undone, The Dream-Quest and The Web of Dreams, The Innsmouth Conspiracy, Edge of the Earth, The Scarlet Keys, The Feast of Hemlock Vale, The Drowned City, Children of Blood, the five Return-to boxes, Guardians of the Abyss, Fortune and Folly, and 17 side scenarios as one-scenario campaigns. For each scenario it takes the reference card, the encounter sets, the acts and agendas in stage order, the locations put into play and the starting location, the cards set aside, the layout, the chaos-token values per difficulty, and the resolutions with the log entries, cards, trauma and experience they give. Per campaign it takes the chaos bag of each difficulty and the packs its cards come from. A rerun writes identical files. A campaign folder of the same id in `content/campaigns` is a hand-written replacement and is never generated.

What "generated" means in play, and what the import approximates (its notes are in `.cache/import-campaigns.log`):

- **Rules are partial.** A card without written behaviour shows its text and has no effect: treacheries are drawn and discarded, acts and agendas advance by their clue and doom values, and scenario mechanics (supplies, vengeance, keys, the exploration deck, Frost) are missing. The new-game screen says so under each generated campaign.
- **Endings.** When the last act or agenda advances and no script ended the game, the scenario ends with the resolution its back names ("→R2"), else the first resolution for an act and no resolution for an agenda.
- **Connections** are not in any source: locations next to each other on the guide's layout are connected, and locations without a place on it are connected to every location.
- **Chaos tokens:** each symbol token's value is read from the reference card; a value of X or one it can't read is −2 (215 of them). The engine has no frost or blood tokens, so they are left out of the Edge of the Earth and Children of Blood bags.
- **Setup:** a choice in the guide's setup takes its first option; 31 scenarios name no location the import could find and start at their first location; 7 scenarios with no usable setup and 9 fan-made side scenarios are skipped, and the fan-made campaigns are not imported.
- **Order:** the guide's listed order is played; campaigns that let the players choose the order or insert interludes don't.
- **Music:** generated scenarios play the default ambient bed.

Only the list of campaigns is in the first download. A generated campaign's scenarios, its text and its icons (`public/icons/sprite-campaigns.svg`, 2 MB) load when it is picked, and its card packs when it starts or a saved game of it is restored. With them the main JS chunk is 1,874 KB (493 KB gzipped), against 1,742 KB (464 KB) before.

To write a campaign by hand, create `content/campaigns/<id>/` with a `campaign.json`, one JSON file per scenario and, if needed, `scripts/<scenario>.ts`; use Night of the Zealot as the template. ArkhamDB has no location connection data, so each scenario file lists its `connections` as code pairs (and any one-way ones as `oneWay: [from, to]` pairs) and its `layout` as grid positions.

**Keywords:** the card details and the card modal explain each keyword a card has (Hunter, Retaliate, Alert, Aloof, Massive, Surge, Peril, Fast, Patrol, Elusive, Swarming, Concealed, Exceptional, Myriad, Bonded, Permanent, Seal, Uses, Victory) in a sentence or two, worded after the rules reference (the English rulebook in `inspired/`, and `inspired/Arkham_Horror_LCG/документы/Rules_Reference.pdf` for Russian, with the names Russian cards print). The texts are the `kw.*` strings in each locale's `ui.json`.

## Playing

- **Cards:** the title menu's **Cards** opens a catalog of every card and investigator in three tabs (Investigators, Player cards, Encounter cards); opening it loads every card pack (a progress line, about 4 MB, cached by the browser). Filter by class, type, cycle and pack, level, cost, skill icons, slot, trait, encounter set (Encounter cards), and whether the card **works in the game**, and search name, traits and text in the game's language (English names also match); the filters combine, the count updates, and they are kept until the app closes. The results are a grid of card images, paged sixty at a time as you scroll, or a compact list; on a phone the filters open as a drawer. A card's page shows both sides, its details, pack and encounter set, and a badge: *works in the game* (its behaviour is written, or it has no rules text to run) or *text only*. An investigator's page adds the back with the deckbuilding rules, the signature cards and weaknesses as links, and the starter deck. Scans the game doesn't host (every pack but the core) are linked from arkham.build's CDN (ADR-0008); the table never uses them.
- **Title screen and new game:** the game opens on a title screen over the rulebook's cover painting: **Continue** (when there is a game, a campaign or a save), **New campaign**, **How to play** and **Settings**. The other menu screens sit on the rulebook's parchment. New campaign is a short wizard with Back and Continue: pick the campaign (each tile shows the first scenario's reference card, the number of scenarios, the campaign guide's opening text, usually an epigraph, and the scenario names; **More** opens a long one without picking the campaign), tap investigators (up to four; the avatars get badges P1 to P4 in tap order, the first is the lead, tapping again removes one and closes the gap), pick a deck for each, pick the difficulty, then check the summary (avatars in order, the chaos bag, the first scenario) and press **Begin**. Difficulty is shown as the bag itself: four cards with the tokens grouped and the bag's average modifier (the lower, the harder). The settings screen holds language, tapping decks to draw, drawing tokens by hand, pace, tips, **Reset tips**, music and sound effects. **Decks:** on the wizard's deck step each investigator has **Edit** (the chosen deck, a starter or a saved one) and **New empty deck**, which open the deck builder: the deck as a list by type with each card's cost, level, copies and glance chips, the signature cards and weakness slot apart, and beside it the catalog's card list narrowed to what the investigator may take. A card that can go in has a **+**; any other says why in plain words ("3 copies of Machete; the limit is 2", "Too many cards of level 0 beyond the main options: at most 5", "excluded"). Any card can be removed; there is no swap limit, only the deckbuilding rules, which are the snapshot's own (classes and levels, traits, tags and text patterns, card types, uses, per-option limits, "at least" counts, exclusions, copies by title across levels, the signatures and the weakness). The builder shows the deck's validation as it changes and won't save an invalid deck. Pick the basic weakness or leave it random. Saving makes a custom deck (named "Roland · 18 Oct" unless you rename it) kept on this device under `ah:decks`; a starter deck is never changed. Custom decks sit beside the starter decks in later new games, where they can be renamed or deleted; one that no longer validates (a pack removed) is shown with the reason and can't be picked. An investigator whose deck needs a choice made when it is created (a class, an option or a deck size: Mandy Thompson and about a dozen more) or a role (Lola Hayes) is refused by the builder, in plain words, for now. Between scenarios the campaign log shows each investigator's avatar with experience and trauma, an **Upgrade deck** button for each (the builder again, with the experience left: a new card costs its level, at least 1; replacing a card with a higher level of the same title costs the difference; an Exceptional card costs double; Myriad copies come together for one price; signatures and weaknesses are free; it refuses what the experience can't pay and says how much is needed; saving updates the campaign's deck and experience, and the next scenario uses it), the scenarios played, the log and what comes next.
- **The introduction fits the screen:** a long intro scrolls inside its own area, with a fade at the bottom edge while more is below; the card shrinks on short screens (and sits beside the text on a phone held sideways); Continue and Skip stay on screen. The campaign guides' markup is drawn, never shown as tags (`src/ui/guideText.ts`, also used by the resolution screen): `<fancy>` in Caveat, `<typewriter>` in TT2020 Style E (both SIL OFL, in `public/fonts`, TT2020 is 3.4 MB and loads only when a typed line shows), `<game>` and `<innsmouth>` in Teutonic (the guides' About Dead font is "all rights reserved", see `public/fonts/LICENSES.md`), `<smallcaps>`, centred and right-aligned blocks, indented quotations, strikethrough; a tag it doesn't know shows its text. Campaign tiles keep stripping the markup (they show short plain text).
- **Starting a scenario:** the table is empty while you mulligan. Click cards in your hand to put them on the "to redraw" row above it; click one there to take it back. **Redraw** sends them face down into your deck and deals new ones (**Keep hand** if you picked none). After the last mulligan the scenario is introduced: its name and story with the agenda, then the act, each large in the middle until you press **Continue** (or Space / Enter); each then flies to the act/agenda panel, and the starting locations are dealt face down from there, turning over where an investigator starts. **Skip introduction** puts everything in place at once. A loaded game skips the introduction.
- **On a phone:** held sideways (a screen 500 px tall or less, or 900 px wide or less) the table switches to the phone layout. The map fills the screen under a thin bar with the phase initials, the avatars, the Journal and the chaos bag as icons. The act, agenda and piles live in a drawer on the left (swipe in from the edge or tap its handle; tap outside to close), the Journal in one on the right (its icon in the bar). Your hand is a drawer along the bottom: the tops of the cards peek out, playable ones higher and outlined; tap or swipe up to open the fan, tap a card to play it (the drawer closes), tap outside or swipe down to close. The instruction bar sits above the hand and also holds Draw, Resource, Investigate and the act's Advance. Your cards in play are a column on the right edge; its handle widens it to readable cards with their buttons. Focus, Whole map and Undo are icons on the left. The skill-test screen, the showcases, titles, tips and the avatar choices fit the short screen, and card details open full screen. **Touch:** tap a card, room or marker to look at it (its details, nothing chosen), tap it again to choose; hold your finger on a card to open it full size; drag your marker to move as before. Held upright, a phone shows a card asking you to turn it; the game waits as it was. A mouse keeps hover and single clicks everywhere.
- **Tap decks to draw:** with the setting on (the default), every draw in play waits for the drawing investigator to tap the deck: the upkeep draw, each investigator's encounter draw in the mythos phase, draws from card effects (one tap for "draw 2 cards"), Surge (a second draw, a second tap). The deck lights up (the investigator's own, or the encounter deck), the rest of the table dims as for any choice, and the bar says "Tap your deck to draw a card" or "Tap the encounter deck to draw" with a Draw button; on a phone the left drawer's handle glows too. The Draw action is the tap itself: on your turn your deck is lit and tapping it (or the rail's Draw) draws at once. Opening hands and the mulligan redraw never wait. The wait is a pending choice in the engine (kind `draw`), asked for by the setup's `tapDecks`, so saves, replays and Undo see an ordinary choice, the bot taps for itself, and games saved before the setting replay unchanged.
- **Players:** every investigator is an avatar in the top bar, in turn order, with health and sanity under it. In the investigation phase the avatar of the investigator whose turn it is is ringed, with a pip per action left that empties as an action is spent (a fourth pip for an extra action); those done are dimmed and the defeated greyed; a changed count flashes. **Tap an avatar to look at that investigator**: the play strip and the map show their assets, threats and marker, and their hand; your choices wait, and **Back to Roland** (or the decision passing to someone else) returns. **Tap the avatar on screen to open its sheet**: the investigator card, ability text with its button when it can be used, skills, resources, clues and the hand count; Escape, a tap outside or the avatar closes it. When someone other than the active investigator can act (a commit to a teammate's test, a reaction), their avatar **pulses with a label** ("Daisy can commit cards") and the instruction bar says so with a **To Daisy Walker** button; tap either to switch sooner: with nothing in the middle of the screen the table switches to them by itself after about a second, and no title plays for a help. A test of their own (a treachery Daisy draws in the mythos phase) goes straight to her table instead, like any decision. **Stat bar:** the investigator on screen also has a stat bar in the bottom-left corner, at three quarters of its old size: portrait (tap it for the card), ability (with its button, lit like the rail's, under the text whenever the pending choice offers the investigator's own ability, e.g. Roland's reaction; the portrait glows too, and the avatar sheet has the same button for the phone), health, sanity and skills, with the resources and clues above it as piles of cardboard tokens (5, 3 and 1 resources; 3 and 1 clues) and the hand count (a card back with the number). When a choice is among investigators (who plays next, who takes the damage), the avatars light up in the bar and also appear large across the middle of the screen with the prompt above: a tap on either answers. With exactly one eligible investigator the avatar shows for a second and the choice is made by itself (through an ordinary choice, so Undo takes it back). There is no "Pass to" screen and no "hide hands" setting: the deciding investigator's hand is always shown (an old save's setting is ignored). Anyone sharing a device with strangers will want a later opt-in screen.
- **Round tracker:** the top bar shows the scenario and round, then the round's four phases in order (Mythos, Investigation, Enemy, Upkeep) with the current one lit, the ones played dimmed and Mythos struck through in round 1, when it doesn't happen. The player bar sits beside the phases (see Players below). When nothing is left to spend, **End turn** glows. When a turn begins, or an investigator gets a decision of their own while someone else is active (their own test in the mythos phase), "Daisy Walker's turn" plays across the middle with her portrait. On a narrow screen the phases shrink to their initials.
- **Enemy intents:** every enemy carries a small badge saying what it will do in the enemy phase: ⚔ with its damage and horror when it is engaged and ready to attack, » when it is a hunter with nobody at its location, z when it is exhausted and will rest, … otherwise. The badge follows the state at once (evade an enemy and it rests; engage one and it attacks). Hover the badge, or the enemy for its enlarged copy, for the words.
- **Tips for a first game:** the first time each situation comes up (the mulligan, the scenario's goal, your turn, investigating, moving, playing a card, a skill test, drawing a chaos token, an enemy, taking damage, the mythos and upkeep phases, ending the turn, undo), a small tip card says in a sentence or two what to do, with an arrow to the thing it is about. One tip at a time, only while nothing plays and the game waits for you; it never covers the middle of the screen or blocks a tap, and it goes when you do what it says, when the moment passes, or with **Got it**. A tip seen once isn't shown again on this device (remembered in local storage under `ah:tips`). The settings screen has **Show tips** (on by default, saved with the other settings) and **Reset tips**, which forgets which tips were seen. **How to play** on the title screen sums the game up in five short parts: the goal, a round, your turn, skill tests, enemies and harm.
- **Sound:** cards slide, snap and flip, the chaos bag rattles and the token clinks, tests chime or thud, enemies growl and strike, clues glint, doom tolls, the phase title swells. A card with a matching trait brings its own sound: firearms fire, blades cut, spells whoosh, tomes turn a page. Each scenario has an ambient bed; a tension track takes over in the enemy phase and when the agenda is one doom from advancing, and a fight track while any enemy is engaged. Sounds play when the event is on screen, so they match the pace, and skipped events are silent. The settings screen has **Music** and **Sound effects** sliders (saved with the other settings) and the top bar a mute button. Browsers keep audio off until the first tap, so a reloaded game starts its music on the first interaction. Every clip is CC0 and listed in `content/sounds/sounds.json` with its source; `check:content` verifies the files, licences and size budgets; `npm run import:sounds` rebuilds `public/sounds/` from the originals (or synthesised placeholders) with ffmpeg.
- **Instruction bar:** whenever you have something to decide, the bar under the top bar shows your portrait and says in plain words what to tap ("Tap a card to commit it to the Intellect test, then Done", "Tap who takes the damage"), with the buttons that answer it right there: **Done**, **Pass**, **Keep hand**, **Redraw**, **Take nothing**, **Resign**, and on your turn **End turn** (it moved here from the action rail). The action rail keeps only Draw, Resource and Investigate. While events play the bar steps aside. When the question is about particular cards (where damage goes, what to commit or discard, which enemy, which location), everything else dims: the map, the hand, the play strip, the piles and the portraits, leaving the things you can tap bright and outlined. Choosing an action on your turn dims nothing.
- **The map:** drag empty table (or any card) to pan, scroll or pinch to zoom. The camera starts on the deciding investigator's location and follows the decision; **Focus** brings it back, **Whole map** zooms out to every location. On your turn, drag your portrait onto a highlighted location to move; **Investigate** is on the action rail beside Draw and Resource, or click your location.
- **Cards:** hover any card to see it twice as large with a details column beside it (enemies list their fight, health, evade, attack and the damage on them); click it to use it (several options open a menu). Your assets, threat area and engaged enemies are in the strip above your hand, where each card's actions sit on it as buttons: **Fight** and **Evade** on an engaged enemy, an asset's ability on the asset. The act, the agenda and the scenario reference card (top left) open a viewer: every act or agenda in order with the current one marked (the backs of the ones still to come stay hidden), or the reference card with both sides and the bag's tokens; the act's **Advance** button sits on the act card itself, in the panel and in the viewer. The chaos bag (top right) lists its tokens.
- **Hand:** move the pointer along the fan and it magnifies like the macOS Dock: the card under the pointer rises most, its neighbours a little. A column beside the raised card lists its class, type, level, cost, traits, slots, skill icons and text. Cards rest at 225×315 px and rise to about 288×403. Each card carries a glance badge hanging over its top edge: up to three chips saying what it is for. First what its play or ability does (the combat, intellect or agility icon for a fight, an investigation or an evade; the damage icon with the amount; health or sanity healed; clues, cards drawn, resources gained), then the skill icons it commits, merged by skill. A weakness shows just the weakness icon, a card the data can't describe has an entry in `src/ui/glance.ts` (or no badge), and hovering a chip names it. Next to the clue stack the hand count shows a card back with the number of cards held, turning red over the limit of 8; its tooltip gives the limit.
- **Card animations:** every card travels to where it lands. A card you draw rises face down out of your deck pile, then arcs to the middle of the screen, growing and turning face up (several leave the pile one after another). It stays there, large, with "Tap a card to take it to your hand" under it: tap a card or the dark backdrop, or press Space / Enter, and it slides into the fan (the opening hand flies straight in). Up to four cards stand in a row; five to eight shrink into two rows, more shrink further, and the area never scrolls. Hover or focus a card (long press on a touch screen) and the fan's details column appears beside it, on its left for the rightmost card. Searching your deck or picking from your discard pile shows those cards the same way: "Choose one", or "Choose one, or take nothing" with the none option as a link; tap a card to take it. Played cards fly from the fan to your play area, cards from the encounter deck glide onto the map from where they were shown (see Encounter cards below), and new locations are dealt face down from the act panel one after another. A location that is revealed (when someone moves in) lifts and turns over once the portrait has arrived. Other investigators' draws fly face down to their token. With the system's reduced-motion setting, cards just appear.
- **Locations:** clues lie on them as a pile of clue tokens with the total. Hover one to see its shroud, clues, victory points, connections, who is there and its text beside it.
- **Feed:** what everyone (and the game) does appears under the chaos bag, newest on top, at most 4 lines, fading out after a while. Routine entries from one choice are merged into one line ("Each investigator drew a card and took 1 resource"). Only the big moments (damage and horror, attacks, spawns, defeats, clues, doom, act and agenda advances) also rise from whoever did them over the map. The middle of the screen shows one thing at a time: drawn cards, an encounter card, the chaos draw, a test result or a phase title wait their turn, and floating text waits for them. While an event plays, the map dims except for the cards and investigators it is about. A new phase shows as a chapter title across the middle of the screen, like a film's, with the round under it; it stays until the lead investigator presses **Continue** (or Space / Enter), and only then does the phase play out. While a phase plays out by itself, a caption under the top bar names each step as it happens ("Doom gathers on the agenda", "Roland draws an encounter card", "Hunters move", "Enemies attack", "Upkeep"), and the camera pans to whoever acts (a hunter as it moves, an enemy as it attacks), then returns to the investigator who decides next. Hunters move one beat at a time instead of sliding while something else plays. The Journal shows each step as a section line. **Journal** (top bar) shows the whole history there, scrollable; click a card thumbnail to open the card, Escape closes it.
- **Skill tests:** one screen takes the table from the commit prompt to the verdict. On the left is what is tested (the enemy, location or card; your portrait for a plain test), in the middle its line ("Fight: Ghoul Minion · fight 2"), on the right the cards placed so far with the icons each adds. Along the bottom a strip adds it up as icons: skill, placed cards, each chaos token, "= total vs difficulty". Tap a card in the fan to place it; it flies across. Changed your mind? Tap a placed card of yours to take it back into your hand, until you press Done. The play strip stays usable above the screen, dimmed to the cards with an ability you can use now, so Physical Training and its kind work mid-test. Helpers at the location commit in turn on the same screen: their placed cards carry their portrait, each player can take back only their own, and the strip counts everyone's. Then the draw: one disc per token spills out of the bag, each the size of a real token. Tap one (or press Space / Enter): it flips in place to the token while the others fade, and the token slides into the strip. The token is decided by the game's seeded draw, so the disc you pick doesn't change it. The bag is the painted PNG (`public/icons/chaos-bag.png`, from `inspired/icons`) in the top-right button, the bag modal and the draw. The draw is a toss (`src/ui/toss.ts`, pure, seeded by the test so a reload tosses the same way): the bag flies from its button in an arc, lands with a squash and a hop and tips over, and the tokens stream out of its mouth, each on its own arc, spinning, bouncing with less height each time and rolling to rest flat, with a shadow that follows its height; about 1.2 seconds at the Slow and Tap paces and 0.9 at Normal, on every draw. A face-down token is plain cream like the real ones, with a darker rim and an edge. Under reduced motion everything is simply placed. With "Draw chaos tokens by hand" off in settings a single token flips out of the bag by itself. Last the big total, Success or Fail, and Continue (by hand or at the Tap pace; otherwise the screen closes after a short pause).
- **Encounter cards:** a card drawn from the encounter deck (in the mythos phase, by surge, or by an effect) and a weakness drawn from your deck rise out of their pile and stand large in the middle, face up, with the details column on hover. Nothing they do happens yet: the enemy isn't on the map, no damage is dealt, no test starts. Read it, then tap the card, press **Continue**, Space or Enter; it then goes where it belongs, flying from where it stood: an enemy to its location, a weakness to your threat area, a treachery with a test into the skill-test screen, one with a choice to the spot under the instruction bar. This happens at every pace. Several draws are shown one at a time.
- **Pace:** the settings screen's **Pace** setting chooses how fast events play. **Normal** is the usual speed, **Slow** keeps every event on screen 1.6 times as long, and **Tap to continue** holds each big event (an attack, a spawn, an enemy moving, a defeat, an act or agenda advance) until you press **Next** in the caption, Space or Enter, or click the card it is about. Damage, clues and doom that follow it play by themselves.
- **Used-up assets:** an asset whose every ability spends its uses (Flashlight's supplies, .45 Automatic's ammo, Shrivelling's charges) is discarded once its last use is spent, after that ability resolves; the feed says it is used up. This differs from the printed rules, which leave the empty card in play where it can do nothing.
- **Undo:** the **Undo** button (bottom right, or Ctrl/Cmd+Z) takes back your last choices one by one, back to the last moment something hidden came out: a chaos token, a drawn card, an encounter card, a search or a shuffle. Pressing Done reveals the token, so take a mistaken commit back before that.
- **Hits:** when a card hurts an investigator (the Attic's horror, a treachery, an enemy attack), the card glows red and a streak flies from it to their portrait before the numbers change.

## Debugging

The **Debug** panel shows the seed and state, and has these buttons:

- **Bot** answers choices automatically.
- **Download** saves the action log.
- **Load** replays a saved log; games are deterministic, so a log reproduces a game exactly, which makes it useful for bug reports.
- **Copy report** puts one JSON on the clipboard: the replay log, the campaign, the settings, which investigator was being looked at, the pending prompt and the build version. When something locks up, press it and paste the result into the bug report. If the browser refuses the clipboard, the report appears selected in a text box to copy by hand.
- **Paste report…** opens a box where a pasted report is loaded with **Load**: it replays the game and shows exactly that table, with the report's settings. A text that isn't a report gets a plain message.

In dev builds, the store is also available as `window.__arkham`.
